# 桌面自动化（第一版）

第一版在 Windows 和 macOS 上提供 `Desktop Agent`。主 Agent 仍通过 `delegate_agent` 委派任务，
桌面子 Agent 只持有 `desktop_op`，不会获得文件、命令或项目业务工具。

## 启用

1. 打开「系统设置 → 本地访问策略 → 桌面操作」。
2. 打开「桌面操作」开关。
3. 在「桌面授权策略」选择「请求授权」或「自动允许」。默认「请求授权」：第一次实际执行桌面动作时，
   在对话输入框上方选择拒绝或允许本任务；「自动允许」则直接给当前任务发放授权，不显示授权横幅。
4. 桌面授权按任务生效：允许后不会再为每个点击、输入或截图重复弹窗。
5. 拒绝后会停止当前主 Agent 调度及全部子 Agent；同一任务后续的桌面调用会直接返回拒绝原因，不会重复弹窗。

桌面托管期间按 `Ctrl+Alt+Shift+K`（macOS 为 `Cmd+Option+Shift+K`）紧急停止。停止后当前桌面任务结束，新任务可以重新授权。

## 工作方式

- `windows` 列出当前可见窗口，窗口引用形如 `w1`。
- `snapshot` 截取当前窗口和当前画面，并返回窗口列表。
- `click`、`type_text`、`press`、`scroll`、`drag` 完成输入；每次动作后都会重新截图。
- `close` 结束当前桌面会话，不会关闭用户应用。
- `x`、`y` 是相对最新截图的 `0-1000` 归一化坐标，不是屏幕像素。

截图由主进程生成并保存在 `<运行目录>/userdata/automation/desktop/temp/`。
发给模型的是宽度不超过 1280 像素的压缩 JPEG，只进入当前子 Agent 调用链，不写入工具结果库。

## macOS 权限

开关状态和系统权限状态相互独立。开启「桌面操作」后，设置页会展示本次权限检测结果；缺少权限时
弹出应用内授权面板，列出未授权项目并提供对应系统设置入口。客户端不会主动修改 macOS 权限，
也不会为了切换开关自动退出或重启。关闭开关时只保存开关状态并清掉现有桌面任务授权。

权限结果以主应用进程调用 macOS TCC 的状态为准。不要从子进程或终端进程判断授权，否则同一份
系统设置可能在主应用显示已授权、在辅助进程却显示未授权。实际执行桌面操作时如果系统权限调用失败，
主进程会终止对应 Desktop Agent 对话并提示用户，不会继续重试。

macOS 11 上自动禁用 Electron 硬件加速，避免截图和透明状态浮层触发 ANGLE / EGL 异常后结束主进程；
主进程还会记录未捕获异常并保持应用运行。系统锁屏、休眠或远程桌面断开时仍无法保证桌面自动化。

nut.js 绑定的旧版 `@nut-tree-fork/node-mac-permissions@2.2.1` 与 Electron 37 + macOS 11 不兼容。
项目通过 pnpm override 将它替换为带 x64/arm64 预编译二进制的
`@computer-use/node-mac-permissions@2.2.2`，不使用文件补丁，也不要求本机 Python 编译。
辅助功能和屏幕录制权限仍由 Electron `systemPreferences` 统一判断。

对话调用 Desktop Agent 时，如果总开关已关闭或系统权限不可用，主进程会通知界面立即终止对应的
主对话与子 Agent，并弹出提示，而不会继续让模型重试，也不会退出整个应用。桌面动作前还会做一次
无弹窗的权限复核，防止权限已失效时启动截图。

macOS 上需要在「系统设置 → 隐私与安全性」中为 fs-bot 开启：

- 辅助功能：窗口查询、鼠标和键盘操作。
- 屏幕录制：窗口和屏幕截图。

macOS 只把屏幕录制授权应用到新启动的进程。授予或修改该权限后，需要手动完全退出并重新打开
fs-bot，再开启桌面操作；客户端不会自动退出。桌面任务执行期间也会拦截非用户触发的退出事件。
开发模式授权的是运行 Electron 的宿主程序，打包安装后的授权对象是 fs-bot 应用本身。
Windows 不需要额外的桌面操作系统权限。

## 已实现的安全边界

- 功能默认关闭，必须由用户主动启用。
- 桌面授权与工作区访问策略相互独立；开启桌面操作不会自动放行文件或命令。
- 默认每次桌面任务首次操作都要审批；用户也可在系统设置中明确选择「自动允许」。无论哪种策略，
  授权都按任务发放，任务结束、停止、失败或超过租期后收回。
- 执行期间显示置顶托管状态条；状态条默认点击穿透，右侧停止按钮可点击，也可按 `Ctrl+Alt+Shift+K`（macOS 为 `Cmd+Option+Shift+K`）紧急停止。状态条会从系统截图中排除。
- 同一时间只运行一个 Desktop Agent，避免多个任务同时抢鼠标和键盘。
- 桌面操作和截图全部在主进程或本地原生模块中执行，不开放网络监听端口。
- 系统权限、登录、密码、验证码、支付、删除、覆盖保存、发送和安装确认仍由子 Agent 指令要求交给用户。

## 当前限制

- 第一版以截图视觉定位为主，尚未接入 Windows UI Automation 或 macOS Accessibility 控件树。
- 多显示器下会先识别目标窗口所在屏幕，再从该屏幕截图中裁出窗口；`screen` 目标使用鼠标当前所在屏幕。
- 系统锁屏、远程桌面断开或休眠时不能可靠执行。
- 需要所选模型支持图片输入。不支持视觉的模型无法理解桌面截图。
- 尚未提供独立的全屏操作状态浮层；执行中可通过上述组合键终止输入。
