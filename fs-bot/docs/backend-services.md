# 客户端依赖的服务端能力（admin / member / agent / lm）

桌面端自己不带后端：登录、权限、模型对话、工具与知识库全在 fs-java 的服务端模块里。
这篇文档写清「客户端依赖谁、数据怎么走」，以及**新环境上线时必须手工开通的三件事**——
用户与权限、用户积分、模型网关密钥。三件事都是纯手工操作：fs-java 的 `docs/fs_project_lm.sql` 只建表，没有任何初始数据。

## 客户端只认一个入口

客户端的接口地址只有一个：`.env` 里的 `VITE_APP_API_URL`，它指向 **admin** 服务的 `/api`。
admin 按 `/api/{应用}/**` 把请求原样转发到 `rpc.{应用}.rest`（`web/admin` 的 `ProxyController` / `ApiService`），
所以路径里的第一段就是服务名：`/api/member/...` 找 member、`/api/agent/...` 找 agent。
客户端不直连数据库、也不直连模型网关。

| 配置                   | dev 取值                    | 说明                                                        |
| ---------------------- | --------------------------- | ----------------------------------------------------------- |
| `VITE_APP_API_URL`     | `http://127.0.0.1:7808/api` | 唯一的后端入口，写到 admin 的 `/api`                        |
| `VITE_APP_WEBSITE_URL` | `http://127.0.0.1:5173`     | 登录 / 注册 / 忘记密码跳转的站点地址（fs-admin 开发服务器） |

## 服务清单

端口是各模块 `application-dev.yml` 里的默认值，部署时按实际环境替换。

| 服务                   | 端口 | 客户端用它做什么                                                                                                 |
| ---------------------- | ---- | ---------------------------------------------------------------------------------------------------------------- |
| admin（`web:admin`）   | 7808 | 客户端唯一的 API 入口（按服务名转发），同时是登录时 `module=admin` 校验的那个应用                                |
| member（`web:member`） | 7801 | 登录 / 登出 / 会话校验（`/member/user/login` 等）、会话与 RBAC 数据（用户、角色、资源、应用）                    |
| agent（`web:agent`）   | 7827 | 客户端全部业务能力：`/bot/*`（模型清单、模型对话、工具定义与调用、文件上传、项目分享）、技能、知识库、工具、编排 |
| lm（`web:lm`）         | 7824 | 模型网关 `/v1/models`、`/v1/chat/completions` 等。客户端不直连，由 agent 带服务级密钥调用                        |
| file（`web:file`）     | 7812 | 本机文件上传转存、知识库图片输出                                                                                 |
| bi（`web:bi`）         | 7815 | 可选：项目里引用「数据主题」时取主题清单                                                                         |
| kg（`web:kg`）         | 7825 | 可选：项目里引用「知识图谱本体」时取本体清单                                                                     |

### 一次对话经过谁

1. 登录：客户端 → admin → member（固定带 `module=admin`），拿回 `token`（Spring Session 标识）与用户信息。
2. 取模型清单：客户端 → admin → agent `/bot/models` → lm `/v1/models`（带 `fs.agent.token`）。
3. 提问：客户端 → admin → agent `/bot/chat`（SSE）→ lm `/v1/chat/completions`；会话历史由客户端带回，只落本地库。
4. 工具调用：服务端执行（知识库 / 数据主题 / 知识图谱 / 编排 / 工具方法），本机文件先经 `/bot/upload` 转存 file 服务再按标识引用。

## 上线要手工开通的三件事

### 1) 用户与权限（member + admin 应用）

- 客户端登录固定带 `module=admin`：`/member/user/login` 会用 `admin::` 这一项校验访问权，
  用户所属的启用角色没绑定 **admin 应用** 时直接返回 403 并登出（界面表现为登录后立刻回到未登录）。
- 角色还要授权客户端实际调用的资源（资源键 = `模块:控制器:动作`，客户端的动作一律留空）：

| 资源键             | 覆盖的客户端能力                                                            |
| ------------------ | --------------------------------------------------------------------------- |
| `agent:bot:`       | 模型清单、模型对话、工具定义与调用、文件上传、项目分享（`/bot/*` 全部接口） |
| `agent:skill:`     | 技能清单、技能版本清单（技能管理页与 `@` 引用技能）                         |
| `agent:knowledge:` | 知识库清单（项目里引用知识库）                                              |
| `agent:tool:`      | 工具方法检索与调用测试                                                      |
| `agent:agentic:`   | 可作为工具引用的已发布编排应用清单                                          |
| `agent:compare:`   | 模型清单的兜底通道（`/compare/models`）                                     |
| `bi:dataTheme:`    | 数据主题清单（可选）                                                        |
| `kg:ontology:`     | 知识图谱本体清单（可选）                                                    |

- 知识库图片（`/knowledgeImage/url`）不要求资源授权，只按知识库自身的授权角色判权。
- 维护入口（fs-admin）：**用户中心 → 资源列表**（模块 / 控制器 / 动作，动作留空）→
  **角色列表 → 权限**（应用分配勾 admin，资源分配勾上面的资源键）→ **用户列表**里给用户绑定角色。

### 2) lm：给登录用户开通积分

网关对每一次调用（含 `/v1/models`）都做积分判定：`CreditService.authByKey` 取生效用户的积分记录，
记录不存在或状态不是「启用」时**直接认证失败**（401「无效的认证标识」），余额 ≤ 0 时返回 400「积分不足」。

- 入口（fs-admin）：**大模型 → 用户积分 → 添加（抽屉标题「用户开通」）**。
- 必填口径：用户 = 要使用客户端的登录用户；状态 = **启用**；剩余积分给一个正数（按需再挂速率限制、余额预警）。
- 一个用户一条记录（`fs_lm_credit` 以 uid 为主键），后续充值 / 停用都在这条上改。
- 没开通的表现：客户端模型清单是空的，对话直接报「无效的认证标识」——因为 `/bot/models` 与 `/bot/chat` 走的是同一套认证。

### 3) lm：创建 agent 用的授权密钥，并开启「用户代理」

agent 整服务共用一个密钥：配置文件 `fs.agent.token`（`web/agent/src/main/resources/application-dev.yml`）。
这个值就是 lm「授权密钥」里的一条 `secret`，两边必须一致；**值可以改，改完要到 lm 同步**。

- 入口（fs-admin）：**大模型 → 授权密钥 → 添加**。
- 填法：所属用户选一个服务账号；密钥填 `fs.agent.token` 的值（留空会自动生成 `sk-...`，那就得反过来改 agent 配置）；
  状态 = **已启用**；**勾上「用户代理」**（勾选项全文是「允许携带用户会话令牌，按会话用户记账并扣除其积分」）。
- 为什么必须勾：勾上后，客户端带登录会话访问 agent，agent 把会话标识以请求头 `x-auth-token` 透传给网关，
  这一轮的用量与积分记到**登录用户**头上；不勾就全部记到密钥所属用户头上，登录用户即使开通了积分也不会被扣。
- 密钥所属用户也要开通积分：定时任务、服务端编排、lm 自己调网关（向量化 / 重排序 / 模型清单，用的是
  `fs.lm.token`，dev 里与 agent 同值）都不带会话令牌，会落回密钥属主记账，那条记录缺失一样是 401。
- 模型限制（`modelIds`）留空 = 不限制；填了就只放行勾中的模型，模型自身的「授权角色」另算一层。

### 改密钥时的同步点

1. 改 `fs.agent.token`（agent 的配置）。
2. 到 lm「授权密钥」把那条 secret 改成同值（或新建一条、把旧的停用）。
3. 若 `fs.lm.token`（lm 的配置，lm 自己调网关用）也用的是同一个值，一并核对。

三处保持一致，就不会出现「改了配置之后突然全是 401」。

## 排查对照表

| 现象                                          | 多半是                                                                                | 处理                                                |
| --------------------------------------------- | ------------------------------------------------------------------------------------- | --------------------------------------------------- |
| 登录返回 403 并回到未登录                     | 用户的启用角色没绑定 admin 应用（`admin::`）                                          | 角色列表 → 权限 → 应用分配                          |
| 登录正常，接口报无权限                        | 角色缺对应资源授权                                                                    | 资源分配里勾 `agent:bot:` 等资源键                  |
| 模型清单为空，对话报「无效的认证标识」（401） | lm 里没有匹配 `fs.agent.token` 的启用密钥、密钥已过期；或生效用户没有启用中的积分记录 | 授权密钥、用户积分                                  |
| 对话报「积分不足」（400）                     | 生效用户剩余积分 ≤ 0                                                                  | 用户积分里充值                                      |
| 用量记到服务账号而不是登录用户                | 密钥没勾「用户代理」，或客户端这一路没带会话                                          | 勾「用户代理」                                      |
| 本机文件上传失败                              | file 服务不可用，或目标桶不存在（agent 默认桶 `fs-mcp`）                              | 在 MinIO / S3 建桶或改 `fs.agent.bot.upload.bucket` |

## 约定

- **密钥只写「配在哪」，不写「值是多少」。** 文档里出现的 `sk-just-for-knowledge-dev` 是 dev 配置里的占位值，生产环境必须换掉；
  正文不记录任何真实密钥。
- **这三件事没有脚本能替代。** 服务启动不会自动建积分、建密钥，缺了就按上面的对照表补。
- **端口与配置项以各模块的 `application-dev.yml` 为准**，本文档给的是当前默认值。
