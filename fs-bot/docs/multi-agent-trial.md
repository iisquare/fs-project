# 多 Agent 试运行版

这一版把容易污染主上下文、需要连续多步执行的能力拆成三个专业子 Agent：

项目编辑器为 Browser、Project Tool 与 Desktop 三类子 Agent 各提供一个独立开关，默认全部关闭。
至少一种类型实际可用时，主 Agent 的工具清单才包含 `delegate_agent`，且只能委派已开启的类型；
旧项目和旧配置导入后三类都按关闭处理。

- `Browser Agent`：只持有 `browser_op`，负责网页观察、点击、填表、提取和截图。
- `Project Tool Agent`：开启时持有当前项目已启用、且除技能外的自定义工具；关闭时这些工具直接交给主 Agent 调用。
- `Desktop Agent`：只持有 `desktop_op`，在 Windows / macOS 上查看桌面截图并操作本机窗口、鼠标和键盘。

主 Agent 不直接持有浏览器与桌面工具，仅通过 `delegate_agent` 调度这两类子 Agent；
项目工具则按 Project Tool Agent 开关切换执行边界。委派入口通过
`agent: browser | project_tools | desktop` 参数调度。只有 Project Tool Agent 已开启且当前项目至少启用一个服务端工具时，
`project_tools` 才会出现在 `agent` 枚举中；Project 的 Desktop Agent 开关开启且当前平台支持后，才会暴露桌面委派入口，
实际执行仍受系统设置和审批控制。
文件、命令、技能、记忆和定时任务仍由主 Agent 管理。

同一个主模型回合里如果返回多个 `delegate_agent`，不同资源域会并行执行；混有本地工具的回合仍保持串行。全局最多同时运行 3 个子 Agent，浏览器任务按当前用户串行，同项目的 Project Tool Agent 也串行，避免共享登录态或业务账号被并发修改。

## 上下文与状态

### 默认新任务

使用默认的 `session_mode=new` 且不传 `session_id` 时，每次委派都会新建一个子 Agent 会话：

- 子 Agent 从全新上下文开始，不自动读取上一次任务的完整对话。
- 子 Agent 继承项目系统提示词（作为「项目规则」）、启用后的项目长期记忆与本专业的跨任务经验。
- 浏览器登录态仍由当前用户共用的浏览器 Profile 保留。
- 上次任务的页面引用、按钮 `ref`、一次性业务参数不会自动复用。

### 显式续接

委派结果会返回：

```text
session_id: <子 Agent 会话标识>
```

如果确实是同一任务的后续步骤，主 Agent 再次委派时可以传入这个 `session_id`。子 Agent 会加载该会话之前保存的高层问答，但不会加载完整浏览器快照或服务端工具返回全文。

主 Agent 还可以选择会话模式：

- `new`：始终新开，默认值。
- `auto`：有稳定 `task_key` 时续接该键最近会话；否则只自动续接当前主会话里等待用户或上次中断的同类子会话。
- `reuse`：续接 `task_key` 命中的会话；没有键时续接当前主会话最近的同类子会话。
- 显式 `session_id` 优先级最高。

`task_key` 应由主 Agent 根据稳定业务标识生成，例如 `order-123`、`issue-456`。相似但独立的任务应保持 `new`，不要仅靠语义相似自动复用旧参数。

## Project Tool Agent 的工具装配

### 配置发现

- 项目工具以 `project.tools` 为配置来源。装配时先过滤 `enabled: false` 的引用，再把 `kind: skill` 留给主 Agent 的 `local_skill`。Project Tool Agent 开启时，其余五类服务端工具交给子 Agent；关闭时直接放入主 Agent 的工具清单。
- 新建会话或刷新工具集时，客户端主动调用 `/bot/tools` 获取工具定义与说明，用于配置预校验和后续子 Agent 装配。这不是主 Agent 发起的工具调用。
- 工具定义缺少函数名或说明时会拒绝本次装配，并提示修改项目工具配置；不会用本地模板猜测缺失的服务端能力。
- 服务端工具定义、完整方法说明与参数 schema 是执行口径的权威来源。主 Agent 的委派摘要只读取当前项目配置中的类型、名称和简短描述。

### 主 Agent 的委派描述

Project Tool Agent 开启时，主 Agent 不持有具体项目工具，也不会主动探查工具方法。它只通过
`delegate_agent.function.description` 看到一份由当前启用配置生成的精简能力摘要：

- 只声明实际启用的工具类型及数量，不再固定列出全部五类。
- 最多展开 8 个代表能力；名称最多 48 个字符，说明最多 72 个字符，换行会归一为空格，超出部分明确标注未展开。
- 摘要只用于判断是否需要委派。完整方法描述和参数 schema 不进入主 Agent 工具描述，主 Agent 也不能直接执行这些业务工具。
- 摘要会明确提示“未列出的能力不可假设可用”，避免模型根据类型名称虚构其他能力。

例如项目只启用数据主题时，主 Agent 看到的内容类似：

```text
project_tools 负责当前项目启用的自定义业务工具。
当前启用的自定义能力：
- 类型：数据主题（1 个）
- 代表能力：销售分析（按区域汇总销售数据）
```

能力摘要由 `core/ProjectToolCapabilities.ts` 的纯函数生成，主 Agent 的工具定义在 `core/Toolbox.ts` 中按当前 `remoteRefs` 组装，并由测试覆盖“只启用单一类型”“过滤停用项与技能”“摘要数量上限”等情况。

### 子 Agent 的完整工具定义

主 Agent 调用 `delegate_agent(agent: "project_tools")` 后，运行时才根据当前项目重新取得完整项目工具集：

1. 过滤停用项与技能；
2. 从 `/bot/tools` 获取 functions 定义、方法说明和参数 schema；
3. 把仅属于当前项目的工具定义交给 Project Tool Agent；
4. 子 Agent 通过 `/bot/tool` 执行具体方法；
5. 主 Agent 最终只接收 16 KiB 以内的任务摘要，不接收完整业务 JSON 和逐次调用日志。

因此，方法描述采用“客户端预取并只展开给子 Agent”的方式，而不是由主 Agent 在运行时主动探查。这样既保留了方法选择所需的完整说明，又避免把方法 schema 和中间业务数据重新带回主上下文。

### 提示词与缓存

- Project Tool Agent 的 system prompt 由固定专业角色、项目系统提示词（作为“项目规则”）、最近跨任务经验和启用后的项目长期记忆组合而成。
- 固定提示词要求以工具定义中的说明和参数 schema 为权威来源，不得仅凭名称猜测用法；项目规则只能补充业务口径，不能扩大职责、权限或改变输出协议。
- 主工具集按项目工具引用与记忆开关建立缓存键。工具配置变化会命中新的键；新建会话会主动刷新服务端目录。服务端只更新了方法说明、但项目引用没有变化时，已有缓存不会自动失效，新开会话后生效。

## 状态与自动检测

对话输入区上方会显示当前会话的子 Agent 活动入口，可以查看：

- 等待、运行、等待用户、完成、失败和中断状态。
- 当前轮数、正在调用的工具、耗时和最近消息。
- `session_id`、会话模式与是否续接了旧会话，重启后仍可恢复。
- 每个任务都有“详情”入口，可查看模型正文、思考过程、工具参数、返回结果、状态和耗时；运行中会随执行进度刷新，完成后从本地库恢复。
- 运行中的任务会直接显示在输入区上方，当前轮次、工具和耗时无需先展开浮层。
- 活动卡按“Agent 名称与状态 / 任务目标 / 当前动作与详情入口”三层排布，历史会话也使用同一套卡片视觉。
- 主对话工具时间线里的“子 Agent · 详情”标签可直接打开对应详情窗口；不再在该工具节点下额外占用一整行横幅。
- 详情使用独立窗口，不占用也不遮挡主对话工作区；窗口可移动、缩放，并能放到第二块屏幕。同一子 Agent 会话只保留一个详情窗口，重复打开会聚焦已有窗口。
- 详情窗口复用系统标题栏，内容区只保留一行约 40px 的 Agent 身份栏：类型、状态、当前轮次/工具、会话模式与刷新；不重复任务输入内容。
- 主窗口通过主进程把运行快照转发给详情窗口；详情窗口同时从本地库加载检查点，因此即使错过一条实时事件也能恢复。
- 详情默认定位最新任务，支持按工具任务或异常任务过滤；查看历史时不会被新输出强制拉回，点击“回到最新”可恢复跟随。
- 详情主体复用主窗口的消息气泡与工具调用时间线：任务目标作为用户消息，模型过程、思考、工具调用和最终回复作为助手消息展示。
- 左侧任务导航与右侧对话区使用 `el-splitter` 分栏，导航宽度可拖动并持久化；选中任务只保留背景和左侧强调线，不再显示包围式边框。
- 超过 2 分钟没有进展的“等待进展”提示。
- 单个子 Agent 的停止入口。
- 切到别的对话时，侧边栏会话行会显示子 Agent 运行中或等待用户的标记。
- `waiting_user` 只属于仍在运行的主轮次。主对话这一轮结束后（或应用重新启动后），未再承接的等待会话会转成
  `interrupted` 历史，并保留 `session_id` 供显式续接，不再占用“正在处理”和侧边栏等待提示。
- 侧边栏里“对话进行中”和“子 Agent 执行中”按上下两枚状态点排列，整组在会话行内垂直居中。

子 Agent 运行期间每 30 秒写一次心跳。应用启动、重新登录及后续巡检时，会把超过 2 分钟没有心跳的 `queued/running` 会话标记为 `interrupted`。浏览器子 Agent 被要求用单独一行“需要用户介入：<原因>”报告登录、扫码、验证码或 MFA；旧的自然语言判断仅作为兼容兜底。

客户端使用单实例锁。用户库、子 Agent 运行锁与浏览器 Profile 都按当前用户共享，不允许两个应用进程同时执行，避免同一个 `session_id` 或 `task_key` 被重复消费。

### 跨任务经验

`remember=true` 时，子 Agent 完成后只提取最终回答中的「可复用经验」段落并保存：

- 按项目和专业 Agent 隔离。
- 新任务最多注入最近 5 条经验。
- 经验只作参考，任务中的页面状态、工具状态和业务数据必须重新验证。
- 不保存密钥、一次性参数或未经证实的猜测。
- 子 Agent 状态面板可以按专业 Agent 清空当前项目的跨任务经验；子会话本身不受影响。

## 调度约束

- 子 Agent 全局最多同时运行 3 个。
- 同一个子 Agent 会话不能并发运行。
- Desktop Agent 全局串行，因为鼠标、键盘和前台窗口是整台电脑共享的资源。
- 父会话停止时，会停止它正在运行的模型流，并取消子会话对应的浏览器标签页和本地待处理操作。
- 主会话每轮都有独立取消令牌。子 Agent 即使还在等待工具定义或排队，父轮次停止后也不会被迟到的异步调用重新启动。
- Browser Agent 的文件上传同样经过项目工作区读取策略，不能绕过本地访问授权。
- Browser Agent 只允许导航到 `http` / `https`；`file:`、`data:`、`javascript:` 等协议会直接拒绝，动作结束后的最终页面也会再次校验。
- 子 Agent 最多执行 24 个模型往返和 64 次工具调用；达到上限后追加一次不带工具的收尾调用。
- 单个子任务最长运行 20 分钟，连续 6 分钟没有模型或工具进展时自动失败（为工作区审批留出时间）；在途服务端工具请求会收到中止信号。
- 子 Agent 结果返回主 Agent 前按 UTF-8 最多保留 16 KiB。任务失败仍会返回 `session_id`、失败原因和最后一次模型输出，主 Agent 可以据此决定显式续接或重试。
- 每个模型往返和工具调用后都会保存高层问答检查点与互动明细；详情按需加载，不进入会话列表、心跳或续接上下文。
- 单个正文与思考片段最多保留 16 KiB，工具参数最多 16 KiB，工具返回最多 32 KiB；每个会话详情展示最近 8 次委派。

## 数据表

用户库 schema v13 新增、v14 / v15 / v16 补充：

- `agent_sessions`：保存子 Agent 的独立问答、状态、`task_key`、会话模式、续接标记、结果摘要和脱敏执行轨迹。
- `agent_interactions`：一次委派一行，按需保存逐轮模型正文、思考、工具参数、返回和状态；与主会话表分开，打开详情时才读取。
- `agent_experiences`：保存显式标记为可复用的跨任务经验。

删除或清空父会话时，其子 Agent 会话一起删除，旧子会话不能再被续接；已经写入的跨任务经验保留，供后续同类任务使用，并可在状态面板中单独清空。删除项目会先停止该项目正在运行的子 Agent，再清理该项目的子会话和经验。

每个父会话最多保留最近 50 个子 Agent 会话；跨任务经验按项目与 Agent 去重，每类最多保留最近 100 条。删除项目时会同步删除该项目下的子 Agent 会话和经验。

## 试运行观察点

- 主 Agent 的上下文用量是否明显下降。
- Browser Agent 是否减少主 Agent 对页面快照的处理。
- Project Tool Agent 是否能稳定组合多个业务工具。
- 子 Agent 失败时，主 Agent 是否能依据摘要决定重试、换方式或向用户说明。
- 浏览器登录、MFA 和需要人工补充信息时，用户是否能在可见浏览器窗口中及时接管。
- 停止按钮在委派初始化、排队、模型输出和工具执行各阶段是否都能及时收口。
